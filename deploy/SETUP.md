# Автоматическое обновление сайта aprosop.ru

После этой настройки сайт обновляется **сам**: как только программисты
отправляют новый код в GitHub, через 5–15 минут он уже работает на
aprosop.ru. Заходить на сервер и что-то набирать в терминале больше не нужно.

Настройка делается **один раз** и занимает около 10 минут.

---

## Как это работает (коротко)

1. Программисты отправляют код в GitHub (в репозиторий `whatislove7775/psiho`,
   ветка `claude/psychology-platform-design-n89Ow`).
2. GitHub сам проверяет, что код собирается и тесты проходят.
   Если что-то сломано — на сайт это **не попадает**.
3. Если всё хорошо, GitHub заходит на сервер и запускает обновление
   (`deploy/deploy.sh`): скачивает новый код, собирает, перезапускает.
4. Скрипт проверяет, что новая версия отвечает. Если нет — **автоматически
   возвращает предыдущую версию**, и сайт продолжает работать.
5. В конце GitHub ещё раз проверяет снаружи, что https://aprosop.ru открывается.

---

## Новый (чистый) сервер — одна команда

Beget → VPS → сервер → **«Консоль»**, войти под `root`, вставить и нажать Enter:

```bash
curl -fsSL https://raw.githubusercontent.com/whatislove7775/psiho/claude/psychology-platform-design-n89Ow/deploy/provision.sh | bash
```

Скрипт сам ставит Docker, скачивает проект в `/root/psiho`, создаёт `.env`
со случайными паролями, собирает и запускает сайт, выпускает HTTPS-сертификат
(как только домен указывает на сервер — сам повторяет каждые 5 минут) и в конце
печатает 5 значений для GitHub и пароль администратора. Дальше — сразу **шаг 2**.

## Шаг 1. Один раз — на сервере (последний раз в терминале)

### Как открыть терминал сервера без программ

Если у вас VPS на **Beget**: зайдите в панель Beget → раздел **VPS** →
выберите ваш сервер → кнопка **«Консоль»** (веб-консоль в браузере).
Войдите под пользователем `root` (пароль — из письма/панели Beget).

Можно и через любой SSH-клиент, как вы делали раньше.

### Команда

Скопируйте и вставьте **одну** строку целиком, нажмите Enter:

```bash
cd ~/psiho && git fetch origin claude/psychology-platform-design-n89Ow && bash <(git show FETCH_HEAD:deploy/bootstrap-server.sh)
```

> Если проект лежит не в `~/psiho`, замените `~/psiho` на правильную папку
> (ту, где лежат `docker-compose.yml` и `.env`).

Скрипт ничего не перезапускает и сайт не трогает. Он:

- создаёт отдельный «ключ доступа» для GitHub;
- разрешает этому ключу заходить на сервер;
- печатает на экране **5 значений** для GitHub.

На экране будет примерно так:

```
  DEPLOY_HOST     155.212.128.231
  DEPLOY_USER     root
  DEPLOY_PORT     22
  DEPLOY_PATH     /root/psiho

  DEPLOY_SSH_KEY  ← весь текст ниже, ВКЛЮЧАЯ строки BEGIN и END:

-----BEGIN OPENSSH PRIVATE KEY-----
b3BlbnNzaC1rZXktdjEAAAAABG5vbmUAAAAEbm9uZQAAAAAAAAABAAAAMwAAAAtzc2gtZW
...
-----END OPENSSH PRIVATE KEY-----
```

Не закрывайте это окно, пока не выполните шаг 2.

**Это последний раз, когда вам нужен терминал.**

> ⚠️ Текст между `BEGIN` и `END` — это как пароль от сервера. Вставляйте его
> только в GitHub (шаг 2) и никому не пересылайте.

## Шаг 2. Один раз — в GitHub

1. Откройте https://github.com/whatislove7775/psiho
2. Сверху нажмите **Settings** (шестерёнка).
3. В меню слева: **Secrets and variables** → **Actions**.
4. Вкладка **Secrets** → зелёная кнопка **New repository secret**.
5. Создайте по очереди 5 секретов. Для каждого:
   в поле **Name** — имя, в поле **Secret** — значение с экрана сервера,
   затем **Add secret**.

| Name (имя)       | Secret (значение)                                           |
|------------------|-------------------------------------------------------------|
| `DEPLOY_HOST`    | IP-адрес сервера                                            |
| `DEPLOY_USER`    | пользователь (обычно `root`)                                |
| `DEPLOY_PORT`    | порт, обычно `22`                                           |
| `DEPLOY_PATH`    | папка проекта, например `/root/psiho`                       |
| `DEPLOY_SSH_KEY` | весь ключ, от `-----BEGIN…` до `…END OPENSSH PRIVATE KEY-----` включительно |

6. Рекомендуется (не обязательно): там же вкладка **Variables** →
   **New repository variable**:

| Name            | Value                                        | Зачем |
|-----------------|----------------------------------------------|-------|
| `DEPLOY_BRANCH` | `claude/psychology-platform-design-n89Ow`    | деплоить только эту ветку (иначе push в `main` тоже попадёт на сайт) |
| `SITE_URL`      | `https://aprosop.ru`                         | адрес для финальной проверки (это значение по умолчанию) |

Готово. Со следующего обновления кода всё пойдёт автоматически.

Чтобы проверить прямо сейчас: вкладка **Actions** → слева **Check & Deploy** →
справа **Run workflow** → зелёная кнопка **Run workflow**.

## Как смотреть обновления

- Откройте https://github.com/whatislove7775/psiho/actions
- Каждая строка — одно обновление.
  - ✅ зелёная галочка — сайт обновлён и проверен;
  - ❌ красный крестик — что-то пошло не так (сайт при этом работает на
    предыдущей версии);
  - 🟡 жёлтый кружок — идёт прямо сейчас.
- Внутри видно три этапа: **Build & test** (проверка кода),
  **Deploy to server** (обновление сервера), **Post-deploy health check**
  (проверка сайта снаружи).

Если на этапе **Deploy to server** написано «Deploy skipped» — значит,
секреты из шага 2 не заданы (или push был не в ту ветку).

### Как запустить повторно

- Открыть нужный запуск → справа сверху **Re-run jobs** → **Re-run all jobs**.
- Или вкладка Actions → **Check & Deploy** → **Run workflow**
  (обновит сайт до последней версии кода).

### Как работает откат

- Если новая версия **не собралась** — старые контейнеры даже не
  останавливаются, сайт работает как раньше.
- Если новая версия собралась, но **не отвечает** в течение ~4 минут —
  скрипт сам возвращает предыдущую версию кода, пересобирает её
  и помечает запуск красным. В логе запуска видны последние сообщения
  об ошибке — их можно переслать программистам.
- Вернуть «вручную» старую версию: попросите программистов откатить
  коммит в GitHub (`git revert`) — это тоже задеплоится автоматически.

> Откат возвращает **код**, но не отменяет изменения в базе данных
> (миграции). Обычно это безопасно; если миграция была разрушающей —
> это задача для программиста.

Журнал всех обновлений на сервере: файл `~/.aprosop-deploy.log`.

## Что НЕ меняется автоматически

- Файл `.env` на сервере (пароли, ключи ЮKassa и т.п.) — только руками.
  Список всех настроек — в файле `.env.example`.
- База данных и SSL-сертификаты — не трогаются.
- Если на сервере кто-то правил файлы проекта руками, эти правки будут
  заменены версией из GitHub (но сохранятся в `git stash` на всякий случай).

## Про два репозитория (whatislove и psiho)

- Код ведётся в ветке `claude/psychology-platform-design-n89Ow` и
  отправляется **в оба** репозитория: `whatislove7775/whatislove` и
  `whatislove7775/psiho`.
- **Сайт обновляется только из `psiho`** — секреты из шага 2 добавляются
  только туда. В `whatislove` тот же workflow просто проверяет код и пишет
  «Deploy skipped» — так и задумано.
- Ветка `main` в `psiho` — старая копия, на сайт она не попадает, если задана
  переменная `DEPLOY_BRANCH` (см. шаг 2, пункт 6).
- Магазин в корне репозитория `whatislove` (`src/`, `package.json`) к сайту
  aprosop.ru не относится и не деплоится.

## Для программистов

- Ручной деплой на сервере (если вдруг нужно): `cd ~/psiho && make deploy`
  (или `bash deploy/deploy.sh ~/psiho <ветка>`).
- Health-эндпоинт: `GET /api/v1/health/` — используется контейнером api,
  скриптом деплоя и финальной проверкой.
- На сервере больше **не** выполняется `makemigrations` — миграции нужно
  коммитить. CI падает, если модели изменены без миграции
  (`makemigrations --check`).
- Сменить ключ доступа GitHub: удалить `~/.ssh/aprosop_github_actions*`
  и строку `github-actions-deploy@aprosop.ru` из `~/.ssh/authorized_keys`,
  затем снова выполнить команду из шага 1 и обновить `DEPLOY_SSH_KEY`.
