# «Круги» — групповые встречи

Тематические группы поддержки: 5–12 участников, психолог-ведущий и (по желанию) ко-терапевт, цикл еженедельных
встреч или одна встреча.

## Ко-терапевт

Ведущий приглашает второго **проверенного** специалиста (`/circles/pro/{id}/cohost/`), тот принимает приглашение
на своей странице кругов. После принятия ко-терапевт виден на странице круга (фото, опыт, проверенные документы),
пишет в чат («ко-терапевт»), на встрече — с камерой, как ведущий, и модерирует: выключить микрофон/всем, опустить
руку, удалить участника, комнаты. Нельзя: отменить круг, завершить встречу, менять круг и долю.
Встреча считается состоявшейся, если пришёл хотя бы один из двух специалистов.

Деньги: доля задаётся ведущим (0–70 %, в интерфейсе 90/10…50/50). После `capture_for_call` каждой оплаты
`billing.services.share_captured` переводит процент **заработка ведущего** (после комиссии) из его «ожидает»
в «ожидает» ко-терапевта и создаёт ему собственную строку `Hold` (без клиента, `reason="cohost_share"`) — она
созревает и выплачивается обычным путём. Штрафы за поздний выход участника целиком уходят ведущему.
Ручной возврат уже списанной оплаты (`refund_captured_call`) забирает только часть ведущего.

## Комнаты (breakout)

Встреча = «Общий зал» (`main`) + до 6 комнат. Ведущий и ко-терапевт открывают 2–4 комнаты (участники
распределяются поровну), перетаскивают участников или выбирают нескольких и жмут «Сюда», сами заходят в любую
комнату, ставят таймер (по истечении ведущий автоматически возвращает всех), пишут сообщение во все комнаты,
возвращают всех одной кнопкой. Участник видит, в какой он комнате, таймер и уведомление о переводе; сам
переходит, только если ведущий разрешил («Участники могут переходить сами»).

Каждая комната — отдельный mesh: сервер (`group.py`) хранит состояние комнат в кэше и пересылает SDP/ICE только
между пирами одной комнаты, поэтому соединений (и звука) между комнатами нет даже у модифицированного клиента.
При переводе клиенты закрывают соединения с теми, кто теперь в другой комнате, и открывают с новыми соседями.
В комнатах — те же псевдонимы, персонал доступа к встречам не имеет.
Код: `apps/api/apps/circles`, `apps/api/apps/signaling/group.py`, `apps/web/src/hooks/useGroupCall.ts`,
`apps/web/src/components/circles/*`, страницы `/app/circles`, `/pro/circles`, `/admin/circles`, `/circle-room/[id]`.

## Приватность

- В каждом круге участник получает новый псевдоним («Участник-Лиса») и `handle` — случайную строку.
  Во всех ответах API, в чате и в сигналинге фигурируют только они. Id пользователя и alias не видит
  никто: ни другие участники, ни ведущий, ни персонал (персоналу список участников не отдаётся).
- На встрече участник — всегда 3D-аватар. По умолчанию это **новый аватар для этого круга**
  (`randomAvatar("circle-" + handle)`), чтобы специалист, знакомый с клиентом по диалогам, не узнал
  его привычный аватар; свой аватар можно выбрать в лобби. Настоящая камера — только если ведущий
  включил `allow_real_faces` и участник подтвердил «Показать лицо»; сервер пропускает `face: "real"`
  от участника только при этой настройке.
- Маска голоса (`useVoiceTransform`) в кругах включена по умолчанию («Нейтральный»).
- Чат зашифрован на диске (`apps.chat.crypto`), исчезающие сообщения удаляются `circles_sweep`;
  новый участник не видит переписку до своего прихода.

## Деньги (apps.billing, без форка)

`billing.services.hold_for_group(ref, …)` создаёт обычный `Hold` без созвона (`reason="group"`).
Дальше — стандартные `capture_for_call(ref)` / `release_for_call(ref, reason)`:

| Событие | Что происходит |
|---|---|
| Запись, цена за встречу | заморозка на каждую будущую встречу |
| Запись, цена за цикл | одна заморозка; запись закрывается, когда цикл начался |
| Встреча прошла (ведущий заходил) | списание заморозок этой встречи; цикл — после первой состоявшейся |
| Ведущий не пришёл | полный возврат за встречу (`specialist_no_show`) |
| Участник вышел | будущие встречи — по правилам отмены созвонов (бесплатно ≥ `BILLING_FREE_CANCEL_HOURS`, иначе штраф `BILLING_LATE_CANCEL_PENALTY_PERCENT`) |
| Ведущий исключил / отменил круг / отменил персонал | полный возврат несостоявшегося |

`settle_overdue_calls` групповые заморозки пропускает — их рассчитывает `circles.services.sweep`
(команда `circles_sweep` в сервисе `scheduler`, плюс ленивый запуск из API).
Лист ожидания бесплатный: при освобождении места первый, у кого хватает денег, становится участником.

## Групповой звонок: mesh

Каждый участник держит по одному `RTCPeerConnection` на каждого другого (полный граф).
Сигналинг `/ws/circle/<room>/` — только адресная пересылка SDP/ICE (`signal {to}`), состояние
(микрофон, видео, рука, «только звук»), команды ведущего (выключить всем/одному, опустить руку,
удалить, завершить). Perfect negotiation по парам: «вежливый» — пир с большим id.

**Бюджет на пира** (адаптивно, `videoCaps`):

| Кто | Видео | Потолок битрейта | Аудио |
|---|---|---|---|
| Участник (аватар) | 240p, 12 fps | 160 кбит/с, но не больше 1,2 Мбит/с ÷ число пиров, которым мы шлём видео | Opus mono 32–40 кбит/с, FEC |
| Ведущий / ко-терапевт (камера) | 480p, 20 fps | 600 кбит/с, но не больше 2,4 Мбит/с ÷ то же | то же |

**Не больше 6 входящих видео** (`MAX_VIDEO`). Каждый клиент сам выбирает, чьё видео ему нужно: специалисты
своей комнаты + активный и недавние говорящие. Остальным он шлёт подсказку `signal {hint: {video: false}}` — они
перестают отправлять ему видео (`replaceTrack(null)`, без переговоров SDP) и не тратят на него отдачу. Такие
участники показаны маленькими аватарами в полосе «только звук»; звук идёт от всех всегда. Когда кто-то
заговорил, он через ≤ 2,5 с попадает в большие плитки.

Режимы качества: `high` → `low` (половина битрейта, 10–15 fps, 240–360p) при ограничении по полосе/потерях
3 проверки подряд → `audio` (видео не отправляется, и пирам сообщается `audio_only`, чтобы они не слали видео нам)
при потерях > 15 % или RTT > 900 мс. Пользователь может включить «Только звук» сам.

**Пределы mesh** (14 пиров = 13 соединений у каждого):

- Приём: ≤ 6 видео × ≤ 0,6 Мбит/с + 13 × 0,04 аудио ≈ 1,5–2 Мбит/с — терпимо и на мобильном.
- Отдача участника: видео только тем, кто его запросил (обычно 1–6 пиров, говорящий — всем): 6 × 0,16 + 13 × 0,04
  ≈ 1,5 Мбит/с в худшем случае; специалист, которого смотрят все: 13 × (0,18 + 0,04) ≈ 2,9 Мбит/с — при
  ограничении включаются `low`/`audio`.
- CPU: до 13 аудио-декодеров, ≤ 6 видео-декодеров, но всё ещё до 13 кодировщиков видео у говорящего.
  Слабые телефоны греются; на них лучше «Только звук».
- ICE/TURN: до 13 пар на клиента; при симметричном NAT весь трафик идёт через coturn (до 14 × 13 потоков).
- Потолок: 12 участников + ведущий + ко-терапевт (`MAX_PEERS = 14`, сервер закрывает лишних кодом 4003).
  Комнаты уменьшают нагрузку: в комнате из 4 человек — 3 соединения.

## Путь к SFU (LiveKit или mediasoup)

Когда понадобятся круги больше 14 человек, запись-без-записи (только аудиостатистика), симулкаст или
стабильная работа на слабых телефонах:

1. **LiveKit** (Go, готовый сервер + JS SDK) — самый быстрый путь: контейнер `livekit-server` рядом с coturn,
   токены доступа выдаёт `MeetingJoinView` (вместо `make_group_token`, та же проверка участия; identity = `handle`,
   name = псевдоним — сервер LiveKit тоже не знает аккаунтов). Клиент: `livekit-client` `Room.connect`,
   публикуем те же треки (аватар из `useAvatarCamera`, голос из `useVoiceTransform`) с симулкастом 180/360p,
   команды ведущего — через `RoomService` API (mute/remove) из Django.
2. **mediasoup** (Node) — больше контроля, но свой сигналинг: наш `GroupSignalingConsumer` можно оставить для
   ростера/состояний, а SDP заменить на транспорт mediasoup-client.
3. В обоих вариантах: каждый отдаёт один поток (симулкаст) вместо N−1, отдача ≈ 0,5 Мбит/с независимо от размера
   круга; сервер SFU видит только зашифрованный SRTP (E2EE LiveKit — по желанию), записи нет.
4. UI (`GroupRoom`) не меняется: `useGroupCall` заменяется на хук с тем же интерфейсом (`peers`, `speaker`,
   `setMyState`, `hostAction`, `tier`, `rooms`, `roomsAction`).
5. Комнаты в SFU — отдельные «комнаты» LiveKit (или подписки по комнате в mediasoup): перевод = переподключение
   к другой комнате с тем же токеном-правом; лимит видео — `setSubscribed`/`setVideoQuality` вместо подсказок.
